# Memory handoffs through project rules and skills

**Scope correction, 2026-09-07:** the issue bodies prescribed retention and
referenced memory handoffs. This experiment does not establish adoption from
standing rules/skills without task-specific memory instructions. Its results
remain evidence about guided workflows. See the
[replacement design](plans/0005-unprompted-memory-adoption.md); no frozen input,
result, or verification record has been changed.

**Agents discovered the installed workflow and retained complete agreements, but
correct memory did not guarantee correct subsequent work.** All 32 sessions
finished. All four initial captures and four permanent revisions preserved the
approved structured content and named approval fields. All 32 components passed
the independent cache-behavior checks; only **19/32** satisfied the complete
artifact contract. Thirteen Claude components flattened the exported policy and
omitted its project identifier and nesting despite retrieving faithful memories.

The [public description](../docs/adoption-harness/MEMORY-E2E.md) was committed and
pushed at `8191a33` before implementation. The
[frozen manifest](../memory-bench/results/memory-routes/2026-09-06-e2e-01/manifest.json),
[original results](../memory-bench/results/memory-routes/2026-09-06-e2e-01/report-01.md),
[corrected action audit](../memory-bench/results/memory-routes/2026-09-06-e2e-01/action-audit-01.json),
and [independent trace audit](memory-e2e-trace-audit-2026-09-06.md) retain the
separate evidence and its limits. No completed or interrupted model session was

## What changed in this experiment

The earlier studies supplied the memory procedure directly and concentrated on
configuration handoffs. This screen tests its delivery through ordinary project
guidance while agents implement runnable components and author real dependent
issues. An installed-condition prompt says only `Work on <actual-issue-id>.`

The harness installs shared AGENTS rules, CLAUDE/GEMINI imports, a project Beads
skill, its detailed memory reference, and a project `bd prime --no-memories`
template. The canonical skill lives under `.agents/skills/beads`; Claude receives
a relative project-skill alias. The detailed procedure is 553 words. The explicit
condition receives those same procedure bytes in each fresh session's initial
prompt, with ordinary issue guidance but no registered memory skill. Both
conditions have the same seeded task requirements, actual CLI, grader, and
memory-body exclusion from prime; actual authored successor bodies can differ. This compares delivery packages, not one isolated rule or sentence.

Each lifecycle implements eight sibling Python cache components: establish an
approved agreement; direct reuse; search reuse; permanent revision; revised direct
reuse; revised search; fully supplied reproduction; and historical reproduction.
The independent checks cover runtime behavior, the complete nested POLICY, and
exact SOURCE/RATIONALE fields. The public README states that interface. Public
tests and any tests agents add remain separate from hidden approved-value grading.

The initial and revision authors choose their actual memory keys and create the
real successor issues used in the direct stages. The harness supplies neither
perfect keys nor repaired missing captures. Four competing memories are present
initially. Only actual retained state travels forward, including mistakes.
Source code, tests, and task history also remain available, and authored tasks
sometimes repeat settings. Those are legitimate alternative sources. This screen
does not prove that memory was necessary to obtain a correct answer.

There is no automatic capture hook or completion guard. Startup rules call prime;
actual recovery after compaction was not exercised. The implementation uses
legacy `bd remember`, `bd memories`, and `bd recall`, not the proposed Memory bead
type or its production reference/revision semantics.

These are four correlated lifecycles using one synthetic case. The 32 successive
complete-memory checks are availability checks, not 32 independent captures.
There were no missing successor tasks, unrun slots, interrupted sessions, or
instruction-package changes. All 32 issues were closed, including the 13 with
incorrect exported interfaces; completion claims and issue status are not grades.

- **Discovery and instruction delivery:** Claude activated the native Beads skill
  in 8/8 installed sessions; its complete skill body was delivered each time. It
  explicitly read the detailed memory reference in 5/8. Codex explicitly read
  both full files in 8/8 installed sessions, using the documented fallback. Both
  ran prime in all sessions. Automatic AGENTS loading remains indirectly observed
  through installed files and behavior rather than separately instrumented.
- **Capture omission and information loss:** no omitted or incomplete approved
  contracts in four initial captures or four revisions. Both original and revised
  structured agreements and named approval fields survived. This establishes
  fidelity to the supplied synthetic source, not verification that an external
  approval really occurred or that arbitrary prose would be captured completely.
- **Direct lookup:** all eight agent-authored direct tasks were present and cited
  actual retained keys. All eight direct stages fully recalled the applicable
  agreement. Complete artifact success was 5/8; the other three preserved the
  values but flattened the exported structure.
- **Search and full lookup:** seven of eight named search stages obtained the
  selected record through a query followed by full lookup. Claude installed's
  revised search queried literal `list`, got no matches, listed all memories, and
  then fully recalled the right record. Discovery allowing that fallback was
  8/8; complete artifact success was 5/8. Neither successful command execution
  nor output visibility proves model attention or causal use.
- **Application:** all 13 composite failures have correct runtime behavior and
  exact SOURCE/RATIONALE fields, but wrong POLICY structure. All eight Claude
  explicit artifacts fail this way. Claude installed gets revised direct, revised
  search, and supplied reproduction right, while its first four and historical
  components flatten the policy. Earlier flattened code was available and often
  read; correct code was available for one later success. Mixed results when
  reading the same earlier code support a possible influence, not a controlled
  causal explanation. The initial agents' tests also reinforced their mistaken
  interface. More memory calls did not fix that error.
- **Historical mutation:** all four original historical bodies stayed byte-identical
  throughout their lifecycles. Historical work retained the standing revised
  agreement. Its complete artifact result was 2/4 because both Claude historical
  components flattened POLICY. These mutable legacy notes still have no mechanical
  protection against future edits or concurrent changes.
- **Unnecessary work:** 23/24 reproduction tasks made zero memory writes. Claude
  explicit's revised search resaved identical content under the existing key and
  read it back. No new duplicate identity appeared, so comparing final memory maps
  alone would miss that work. All four supplied controls made zero writes;
  three also made zero reads. Claude explicit searched and recalled before
  implementing its fully supplied task. Supplied artifact success was 3/4.

Exact field checks do not certify surrounding narration. The trace audit found
Claude claims of an "immutable" legacy snapshot, "exact" reproduction despite
the flattened interface, and an "update" that changed no memory bytes. The report
retains these separately from the faithful stored approval fields.

## Smallest useful changes, ranked

1. **Make the required artifact interface checkable.** Add a public conformance
   check for required structure and identifiers, independently of hidden approved
   values. Compare implementation against the approved agreement and task
   requirements; agent-written tests can encode the same mistake as the artifact.
   This directly addresses the 13 observed failures. It is a proposed treatment,
   not a success claimed by this frozen run.
2. **Keep the tested workflow delivery small.** Generate shared AGENTS routing,
   host imports, a Beads skill with a memory branch, and prime orientation during
   project setup. Preserve the occasions: capture a newly approved durable
   agreement or permanent revision before closing; retrieve missing prior context
   before implementing; reproduce without resaving. Installed delivery reached
   both tested hosts, but this sample cannot establish its superiority to direct
   prompting or eliminate the extra resave/reads seen here.
3. **Use actual Memory identity and protected revisions in the next production
   slice.** Carry actual references in issues, distinguish current from pinned
   historical intent, protect old bodies, and reject stale writes. This screen
   did not validate those mechanisms. Earlier experiments' historical rewrites
   show why instructions alone should not be their permanent substitute.
4. **Improve ergonomics from concrete departures.** Two failed `bd memory list`
   attempts and the silent literal-query interpretation of `bd memories list`
   justify clearer discovery/help. A listing is useful but should be labeled as
   such. Consider aliases only after validating their meaning; do not silently
   redefine a valid search term as a command. Preserve a readable preview beside
   the faithful record. Structured agreements need their structure; prose memories
   do not all need JSON.
5. **Replicate before broad reliability claims.** Clear the three host blockers,
   exercise the actual Memory type with the same handoffs, add distinct task
   families and repeated lifecycles, and test accumulated native memory and
   compaction. Keep trace review and independent downstream-work checks alongside
   adoption metrics.

Atbrace's account of a large transcript collection, observed adoption, consistent
tool conventions, JSON responses, and feedback-driven iteration remains attributed
practitioner evidence, not a verified measurement from this project. Its useful
application is the transcript-and-feedback loop used here: distinguish discovery,
capture, loss, retrieval, application, historical mutation, and extra work. The
observed attempted commands provide concrete interface evidence. Remembered tool
avoidance remains an unobserved hypothesis; workaround advice should record
version, circumstances, and evidence rather than becoming a timeless prohibition.

The simplest supported handoff is: read the assigned issue; use a complete supplied
agreement directly, or fully recall its actual key, or query and then fully recall
the applicable record; capture only a new or permanently revised approved
agreement, preserving exact scope, structure and source, and check its readback;
retain history unchanged; cite the real record when authoring dependent work;
verify the resulting work before closing. The stored handoff succeeded in these
four lifecycles. Correct application did not. A small synthetic success in capture
is not a bulletproof end-to-end memory system.
