# Admission for ordinary-task memory adoption

The user authorized pushing the qualified harness and running the experiment on
2026-09-07. Commit `1166ecd` was pushed to `origin/csells/memory-routes-experiments`
before this experiment's implementation. This admission records decisions made
before any scored session, not conclusions about agent adoption.

## Independent tasks and review

Two independent authors received business briefs without the memory intervention
or investigation documents. They produced HarborPass renewal work and Northbank
reconciliation work in separate scratch directories. Each includes six cumulative
issues, a starter application, public examples, hidden JSON cases, and a separate
reference implementation. Each reference and its graders share an author; they
are independent of the later evaluated agents, not independent human authors.
The authors then cross-reviewed the other family's complete visible context and
reference behavior after learning the experimental question.

Both original stage-3 tasks introduced separate historical agreements. Review
found that new scoped captures could be justified, so both were revised in new
directories to reproduce already-established release-1 behavior with its complete
rules supplied. All original drafts and validation evidence remain preserved.
A carriage-return CSV quoting defect in the reconciliation reference/grader was
also corrected and covered by an explicit case and a defective variant.

Final cross-review passed 379 hidden and six public HarborPass cases, and 182
hidden and 29 public Northbank cases. The exact evaluator runtime and read-only
sandbox separately passed all **561/561** hidden reference cases. Four HarborPass
and ten Northbank defective variants are rejected by the authors' sensitivity
checks. Final corpus lives in
[memory-unprompted-corpus](../memory-bench/fixtures/memory-unprompted-corpus/).

Every issue requests software behavior. None instructs capture, retention,
memory lookup, memory-key creation, or a handoff. Public examples are delivered
only at their applicable stage. Earlier examples remain available as historical,
individually selected files; later business changes explicitly supersede their
current-behavior expectations. No previous code, issue, or record is removed to
force memory use. The old `memory_e2e_corpus._follow_up` fails the negative control
because it explicitly requests a retained-agreement reference.

The entire memory intervention is the generic
[instruction package](../memory-bench/fixtures/memory-unprompted-package/).
Both arms install the issue skill, canonical AGENTS.md, supported host entry
points, and the same prime orientation and real memory-capable Beads CLI. The
treatment adds general memory occasions and a skill reference; it contains no
task-specific values or example domains. Static skill validation passes for
both rendered arms. The existing eight integration sessions establish the same
delivery paths, commands, authentication, and state transfer; no new explicit
tool exercise is counted as adoption.

## Host admission and limits

All four previously qualified primary models remain pinned. OpenCode's strict
marker and omitted-command failures remain failures in the original report.
Independent review admits it to adoption measurement because instruction delivery,
tools, real capture/search/full lookup, and state transfer worked. Poor adherence
is behavior to measure, not grounds to exclude the requested host. This is an
explicit pre-cohort admission decision; it does not rewrite its 0/2 strict result.

The main comparison disables supported native memory in fresh isolated profiles.
Claude's separate normal condition restores automatic memory and carries its
actual native files. Codex's default memory feature is already off. OpenCode has
no configured automatic extractor; repository notes persist, while conversation
databases/config are fresh. zcode's headless runtime disables extraction even
with its normal memory-use switches. Normal conditions test these disclosed
headless profiles with fresh personal state, not each user's entire customized
installation or accumulated history. Equivalent native profiles are replications.

There are 96 main slots: four hosts × two arms × two families × six stages. The
first three stages form a 48-session checkpoint retained within those 96. A
separate 24 slots use normal native switches on HarborPass in the memory arm.
Order is deterministically counterbalanced within hosts before launch.

Each session has a 420-second wall deadline. Claude uses its $1.50 CLI stopping
threshold; in-flight usage is not a guaranteed invoice cap. Its qualification-based
30-session estimate is $5.26 at reported list prices, with more work likely to
cost more. Codex subscription usage and zcode provider-plan charges are not emitted
as dollars. OpenCode has no remote charge; local compute is unpriced. Actual
reported usage/costs will be retained separately. No new authentication or billing
route is introduced and no started session is automatically retried.

## Grading and operational safeguards

Hidden expected JSON stays in the parent evaluator. Candidate programs receive
only ordinary input cases inside a read-only sandbox that denies access to hidden
files and the source repository. JSON comparison checks complete structure and
types, rejects duplicate keys, and does not accept an agent's success claim.

Grade the complete current artifact independently. Assess actual saved records
and returned bodies separately for useful scope, factual fidelity, omitted
requirements, unsupported provenance, revision correctness, and historical
mutation. For HarborPass, decision fidelity includes applicable lead time, tenure,
autopay eligibility, percentage, floor rounding, cap, and cents. For Northbank,
it includes UTC instants, inclusive/exclusive boundaries, fixed ledger cutoff,
and applicability to current versus historical operations. A deliberately scoped
note need not repeat every application-interface field; incomplete preservation
of the agreement it claims to capture is information loss.

Stages 1 and 4 provide new-decision/finding and permanent-revision opportunities.
Stages 2, 5, and 6 provide subsequent-use opportunities: 48 main and 12 normal
slots, including legitimate alternative sources. Stage 3 supplies a reproduction
control: 16 main and four normal slots. Do not automatically label every control
write a duplicate: a new useful fact or justified scope must be distinguished
from repeated capture of an unchanged agreement.

Report search and direct lookup separately. A recall after search is part of the
search route; direct use requires a reference known before that discovery. A full
body returned by search differs from preview-only discovery. Do not supply keys
or repair absent captures to manufacture route coverage. Agent-created reminders
remain preserved and any later instructed reuse is separated from uncued use.
Administrative snapshots are not agent memory calls.

The runner verifies complete review-hash coverage and freezes actual source,
task/package bytes, executables, and live profile hashes. It checks them before
and after sessions and before phase completion. A regression demonstrated and
fixed the previously missing post-final-session check. Results publish atomically
without replacing earlier evidence. A claimed unfinished slot cannot be rerun.
Host failures retain blocked slots while independent hosts continue; changed
common inputs stop new starts across hosts. Later phases require explicit
checkpoint inspection and preserve the same cohort identity and inputs.

The [runner](../memory-bench/scripts/memory_unprompted_experiment.py), package,
record grader, and adapters have focused tests; the actual read-only grader and
all four real CLI integrations are also verified. The independent authored app
and deliberate-defect corpus is excluded narrowly from library formatting/type
crawls because its applications share module names and preserve authored bytes.
It is validated by executable references and external cases instead.

A success supports the combined rules/skill package on these tasks and these
host/model profiles. It cannot identify rules versus skills separately, establish
that memory caused correctness when code supplied the same facts, validate the
new Memory bead type, or establish production reliability.
