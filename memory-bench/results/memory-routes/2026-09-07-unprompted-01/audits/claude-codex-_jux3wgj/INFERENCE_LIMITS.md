The checkpoint supports a narrow finding: the generic Beads memory workflow did not induce keyed capture or retrieval in the 12 Claude/Codex treatment sessions observed so far. It does not show that these agents forget all useful information. The exercise deliberately retains code, documentation, public examples, and issue history. Codex used those ordinary sources and, in some sessions, improved their preservation with faithful policy documentation or a substantive issue close reason. Report that evidence separately from the keyed route.

This is a reasonable test of whether the added workflow is adopted during small ordinary coding tasks. It is a weak test of whether memory is necessary for correctness: related tasks can be solved from retained code and documentation, and the repetition-control task supplies the full old rule. All hidden cases passed without keyed capture. Thus the observed coding success supplies no causal evidence of benefit from the memory workflow, and the zero memory actions supply no evidence that external memory is intrinsically useless on tasks where prior knowledge is otherwise inaccessible.

Reading instructions and following them are distinct measurements. Codex read the detailed memory procedure in every treatment checkpoint session but never used its memory commands. Claude entered the skill and had the procedure route available but did not open it. Neither finding justifies silently strengthening the frozen prompts or excluding completed sessions as adapter failures. The absence of task-specific memory hints is part of the intended ordinary-work design, not a task-delivery defect.

Four treatment initial-capture opportunities were missed. Four treatment repetition controls produced no writes. This joint pattern cannot establish desirable selectivity: an agent that never captures also never duplicates. Empty stores likewise leave accuracy, completeness, key choice, provenance, and historical fidelity of keyed records undefined. Retain each planned stage denominator, state why downstream memory was unavailable, and do not convert absent opportunities for actual retrieval into successful direct lookups.

Recommendation strength should track the design: two hosts, two task families, one isolated lifecycle per host/family/arm, short sequential work, and a checkpoint restricted to stages 1-3. There is no basis here for a broad production reliability claim, a reliable latency/cost effect, or a host ranking in long-term knowledge reuse. The remaining frozen revision, current-use, compatibility, and native-memory phases add relevant observations and should proceed unchanged once overall checkpoint admission is complete.

For normal-mode analysis, inspect actual native-memory files as their own output channel, alongside their actual read evidence and keyed Beads records. A native file copied forward is availability; content changing is a write; reading that content is retrieval. Distinguish all three. Do not count administrative snapshots, skill reads, or the mere existence of files as a memory recall. No personal-history injection is part of the frozen normal phase.
