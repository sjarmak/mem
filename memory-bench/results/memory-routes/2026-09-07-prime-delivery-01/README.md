# Prime-delivery experiment evidence

The [results report](../../../../specs/memory-prime-delivery-results-2026-09-07.md)
contains the outcome tables, interpretation, costs, operational limits and ranked
recommendations. The [experiment description](../../../../docs/adoption-harness/MEMORY-PRIME-DELIVERY.md)
explains the agent experience; the [frozen design](../../../../specs/plans/0007-memory-prime-delivery.md)
defines the conditions and scoring.

This cohort compares thin prime, rich prime and a common startup briefing across
six pinned model profiles in four coding CLIs. All task components are ordinary
issue assignments. The startup intervention supplies generic standing guidance,
without task-specific memory reminders, keys or policy answers.

## Evidence authority

- [manifest.json](manifest.json) fixes all 216 slots, conditions, source hashes,
  executable hashes and original profile hashes. Missing assessments remain in
  the planned denominator.
- `frozen-source/` preserves scored inputs and the execution/grading implementation.
  Actual code and memory carry forward, including mistakes and missing notes.
- `cases/<lifecycle>/stage-<n>/result.json` records an assessment. Raw host streams,
  tool observations, launch receipts, actual memory snapshots and independent
  artifact grades live alongside it. A result is not proof of model generation:
  provider-denied sessions can still have assessed artifacts.
- [delivery qualification](../2026-09-07-prime-delivery-qualification-01/result.json)
  establishes working authenticated interfaces and exact guidance delivery in
  explicit diagnostics; it does not count as voluntary adoption.
- [verification and aggregate reports](../2026-09-07-prime-delivery-verification-01/)
  preserve checks and derived outcomes separately from the original results.
- [Finance semantic audits](audits/finance-cp3z5hwq/),
  [Courier semantic audits](audits/courier-begfwz8d/) and
  [workflow audits](audits/workflow-2alw5dw6/) retain independent judgments and
  their exact evidence hashes. Final exports preserve every planned lifecycle.

## Operational history

The original `phases/` failure evidence remains unchanged. The
[first recovery record](OPERATIONAL-RECOVERY.md) documents the lost stdout pipe,
one post-hoc assessment of an already completed turn, and two prelaunch claims
whose downstream sessions remain censored. No inference was repeated.

The first continuation stopped on a raw Codex configuration hash change.
[CONFIG-GUARD-REVIEW.md](CONFIG-GUARD-REVIEW.md) and
[OPERATIONAL-RECOVERY-02.md](OPERATIONAL-RECOVERY-02.md) preserve the independent
review of unchanged effective settings. `recovery-02/` holds exact admission
reviews, exclusive phase claims, durable launch logs and terminal summaries.
The original raw mismatch is reported rather than erased.

Do not rerun claimed slots or replace failed trials. The scored artifacts and
audits are evidence, not resettable test fixtures. Independent assessment,
generation, provider-denial and unassessed-slot classifications are required
before interpreting command counts or apparent success.
