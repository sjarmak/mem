# Smallest improvements suggested by phase one

This is a bounded recommendation draft, not a new experiment design or a claim
about phase-two outcomes. It uses the completed phase-one workflow audit and
Courier semantic audit plus specific finance traces. Frozen scoring, guidance,
records, trials and source remain unchanged.

The strongest case for Memory Beads is a shared, attributable project handoff:
a fresh agent can find an approved agreement, read the exact version it needs,
apply it correctly and preserve a deliberate revision. I would build that. The
weakest assumption is that copying knowledge into a separate store automatically
makes future work more reliable than using the existing approval sources. Phase
one does not establish that assumption. Make the handoff useful first; treat the
save/read counts as diagnostics.

## Ranked changes to consider after this run

1. **Make the capture occasion explicit without making every task a capture
   occasion (fixable guidance gap).** The existing wording says to capture newly
   approved decisions and new verified findings. Courier starts with an already
   durable vendor document. GLM in all three first-stage arms and Luna in the
   startup arm explicitly declined capture because the issue introduced no new
   policy. That is evidence of a defensible interpretation, not proof they failed
   to discover memory. The Courier audit records 5 captures among 17 assessed
   initial sessions: 3 complete and 2 partial; 12 had none. Smallest proposed
   change: distinguish “new approval or permanent revision” from “first reuse of
   an existing agreement that lacks a useful memory entry.” For the latter, allow
   a deliberately chosen source-linked entry when it would improve future
   discovery; do not require duplicate document bodies merely to increase saves.
   Keep fully supplied reproduction and another consumer of an unchanged
   agreement outside automatic capture. If the product requires a full standing
   agreement in memory, say that explicitly in shared workflow guidance, then
   evaluate that product choice as a new condition.

2. **Make recovery of missing knowledge a concrete ordinary workflow step
   (fixable guidance gap).** “Consult issue history” is available now, but a
   default list can hide the closed issue containing the original approval.
   Phase-one receipts show working `bd list --all`, `bd list --status closed`
   and subsequent issue reads; this is a supported path, not an invented API.
   Smallest proposed change: when memory is absent, incomplete or conflicting,
   inspect the available approval document and closed issue history before
   inferring intent from code. Show the exact closed-inclusive discovery command
   and `bd show <id>` in the memory procedure. If neither supplies the missing
   agreement, state the gap rather than manufacturing a standing policy. When a
   source is recovered, attribute it to that source, not to a prior memory that
   never existed. This preserves legitimate alternatives to memory and avoids
   teaching agents that an empty search means there is no approved decision.

3. **Separate approved policy, implementation inference and verification evidence
   inside the record (fixable truthfulness failure).** Sonnet/Courier/rich-prime
   stage 1 saves a protocol-error response it explicitly calls an
   “inferred-but-reasonable extension” and attributes explicit-version support to
   `AGENTS.md`, although the issue supplies that fact. A readable, successfully
   recalled note can still misstate its authority. Smallest proposed change:
   use a short opening with scope, approval source and exact version where
   available; label implementation choices as such, outside the standing
   agreement. Name the actual command and bounded outcome for validation claims.
   The existing readback rule checks retention, not truth. Preserve a prior
   version for historical work; do not rewrite history merely to make prose look
   current. This proposal does not require JSON for all knowledge: exact
   structured agreements should keep their structure, while prose can retain
   rationale and qualifications faithfully.

4. **Disambiguate the real CLI from the skill entry point, and make failures
   teach the correct command (fixable ergonomics).** Six phase-one Haiku sessions
   called native `Skill(beads, args="prime --no-memories")` without executing
   `bd prime`. Forty-seven successful CLI prime calls produced only 46 verified
   full-output exposures because one was piped through `head -50`. Seven failed
   calls attempted an unavailable `bd memory` namespace. Smallest proposed
   change: show `bd prime --no-memories` as a shell invocation and describe
   loading the Beads skill as loading guidance, not dispatching its arguments.
   Unknown-command feedback should point to the supported remember/recall/search
   verbs. Evaluate an alias only where its meaning is unambiguous; do not turn
   every invented flag into a permanent API. Proposal R8 already requires exact
   commands and truthful truncation. A bounded shared procedure in prime fits
   that proposal, but guaranteed startup submission is not guaranteed
   understanding, and the completed run must decide whether richer delivery is
   worth its context cost.

5. **Keep complete-agreement fidelity and useful partial knowledge as separate
   measures (fixable evaluation/product mismatch).** Sonnet/Courier/thin-prime
   retains global delivery identity, earliest UTC selection, tie handling and
   the provider source, but omits other parts of the complete contract. Its next
   session searches and recalls that note and produces correct work. The rich
   arm's narrower protocol note is also read, with the vendor document supplying
   delivery identity separately. These are informative paths even though neither
   earns the frozen complete-agreement capture score. Smallest proposed change:
   retain that strict score, alongside source-linked partial-entry usefulness,
   omissions relevant to the later task, and successful authoritative-source
   recovery. A pointer is useful only when it resolves and the agent actually
   reads what the work requires. Do not retroactively award full-record or tested
   retrieval-route credit to an incomplete note, inherited code, a bulk list,
   or an unread citation.

## Practitioner input versus measured evidence

Atbrace's transcript-lake account supplies a useful design practice: observe
actual attempted commands and alternative paths, collect specific feedback,
validate recurrent complaints, and improve the canonical workflow. Its reported
150,000-plus transcripts and adoption claims remain attributed and unverified
here. The phase-one audit supplies a concrete local example: 460 actual Beads
executions, 20 failures, including unavailable commands, invalid close flags and
empty-body save attempts. Some later commands correct the attempted syntax.
That supports collecting feedback; it does not prove a universal interface.

No inherited remembered tool-avoidance policy was established in this audit.
Treat that account as a hypothesis for available transcript and memory review.
The existing workaround guidance already asks for tool version, circumstances,
evidence and a recheck occasion; preserve that distinction instead of declaring
old advice permanently authoritative.

## What to cut and what to do first

Cut duplicate instruction prose that does not change an agent's decision. Cut
automatic memory curation on pure reproduction. Keep the shared guidance in one
source and expose it where each host actually operates. First settle the capture
occasion and the useful-entry contract in items 1 and 5. Then make source recovery
and truthful provenance concrete. Finally use the completed delivery comparison
to select the smallest useful entry surface rather than assuming a richer prompt
must win. These are proposed changes; no implementation or additional trials are
authorized by this draft.

Confidence is high in the cited command receipts and observed source/claim
examples, moderate in these proposed fixes, and low in any claim of general
production reliability. This audit does not examine the full implementation of
the proposed Memory Bead type, production-scale corpora or long-lived concurrent
writers. Phase two, model quota failures and the independently audited semantic
outcomes still delimit the final recommendation. The frozen design already
recognizes the capture-occasion ambiguity and partial-record distinction.
