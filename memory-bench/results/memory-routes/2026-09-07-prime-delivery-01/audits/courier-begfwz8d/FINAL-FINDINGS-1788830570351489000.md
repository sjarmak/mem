The initial capture occasion remains ambiguous: the original provider agreement already existed in a durable project document. Missing keyed capture is a failed experimental handoff, not automatically disobedience of the rule about newly approved knowledge. Of14revision sessions with generation, eight wrote a new agreement record, but only three retained the complete current-plus-historical agreement under the declared semantic reading. Six generated revision sessions saved nothing. Five of14generated historical sessions ended with faithful combined current/history information; this includes later source recovery and repairs, not retrospective success for their earlier incomplete captures.

Confirmed common-guidance delivery did not solve capture fidelity. The actual rich prime was delivered to Luna/rich stage4, yet its multiword search returned no result despite a relevant current record. This is a retrieval/discovery failure with correct downstream work, not capture omission. By contrast, several Sonnet and GLM sessions correctly used direct lookup or search followed by full lookup before implementation or genuinely new validation.

Historical correctness required separate inspection. Sonnet/rich first saved a materially wrong P1 winner rule; stage5 read that note, consulted original sources and corrected it. Correct repair receives no successful prior-handoff credit for that leg. GLM/startup stage5 added an obligation for every future protocol to receive accepted-export support on introduction, beyond the accepted P1/P2 request. This is flagged as unsupported future policy under the documented interpretation, not proof of a current behavioral regression. Two lifecycles therefore have observed unsupported agreement mutation. Unsupported provenance and validation prose are tracked separately.

Some faithful combined records require explicit scope interpretation: Luna/startup and GLM/thin place common receipt preservation rules near the current-version paragraph; Sonnet/rich eventually reconstructs required facts across a combined map while its history key alone stays incomplete. The export retains these per-key/combined-map caveats. Limited version-resolution or standing-preservation use is labeled partial; it must not be described as retrieval of the full historical agreement.

No duplicate capture occurred in any of14generated fully supplied controls; only eight had an existing record available to duplicate. Four of those controls still read memory unnecessarily. Correct support fixtures can conceal broader application failure: Qwen/rich eventually copied the correct expected fixture while its actual CLI still returned the wrong receipt order. Qwen/rich stage5 also triggered a frozen observer limitation during automatic compaction; actual generation and artifact evidence remain recorded, with the original host-success failure preserved.

The smallest useful next changes are: make the complete approved handoff the completion criterion for a new durable revision; preserve historical facts and exact discriminators in a faithful record with a readable preview; make failed search prompt query narrowing or catalog/direct lookup; and avoid re-curation merely because an existing policy gained another consumer. Judge each change by subsequent correct work and retained information. This family supplies counterexamples to universal reliability even with confirmed richer guidance; it does not validate the proposed new Memory bead type.
