## Smallest implications supported by this evidence

1. Clarify first introduction of a reusable approved agreement versus another consumer or fully supplied reproduction. Already approved in an issue does not mean already retained for later work.
2. Make failed/incomplete retrieval lead to shorter or alternative domain/version queries and actual source recovery, including closed approval issues. A miss from one query does not establish no memory exists. Confirm source identity/version instead of deriving approval from tests or existing code.
3. Compare the retained record to approved scope, including historical per-line rounding and cap allocation. Readback checks storage, not truth. Keep governing facts, inference, validation evidence and unresolved provenance distinguishable.
4. Preserve current/history meaning during consumer work and revise only with source-backed authority. Existing supplied reproduction should not automatically trigger search/save/readback. Report search overhead separately from duplicates.
5. Use shared rules/skills/prime delivery with explicit host command ergonomics, but judge it by correct later work and faithful information. This small censored comparison supplies no decisive winning delivery surface; attempted commands and attributable practitioner accounts inform proposals, not measured guarantees.
